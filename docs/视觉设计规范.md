## 0. 与现仓对齐

### 0.1 产品与导航

- 对外主称「数字伙伴」（QiZhiDa · PartnerPlatform）；平台名「企智搭 · 数字伙伴平台」/ QiZhiDa · PartnerPlatforms；底层 Agent 为执行内核，不作侧栏主路径。
- **侧栏主项四字对齐**（`role-nav`）：编排入口文案为 **工作伙伴**（`nav.agents`）；审计员为 **伙伴档案**（`nav.agents.auditor`）。产品全称用于页头、登录与文档，不挤进侧栏。
- 品牌主轴（登录页）：**安全零信任 · 先进生产力 · 成本新范式**；徽章「持续验证 / 人机协同 / 成本治理」。
- 侧栏 IA（`AppLayout` 消费 `ROLE_NAV`）：

```text
运营总览
协作：专家协作 → 任务中心
编排：工作伙伴 → 工作流程
能力：模型服务 → 知识中心 → 技能中心 → 记忆中心 → 消息渠道
账号菜单：工作区 · 平台设置（含访问控制 / 持续验证 / 审计中心）
```

- 控制型模块二级菜单顺序：`概览或资产 → 接入与配置 → 验证与发布 → 运行与处置 → 治理与审计`。
- 模块能力以根目录 `README.md` 为准；本规范只约束视觉与交互验收。

## 1. 设计定位

平台是面向企业生产运营与受控执行的数字伙伴控制台。界面优先表达：

1. 当前发生了什么；
2. 用户下一步可以做什么；
3. 是否需要审批 / 是否有风险；
4. 结果能否追溯。

视觉参考现代 SaaS（Linear、Vercel、Stripe）：克制、清晰、稳定、可扫描。  
禁止：装饰性紫粉渐变背景、紫色光晕、AI 插画、无业务价值的指标堆叠、首屏重复 KPI。

## 2. 视觉语言（Token）

定义见 `frontend/web/src/styles/global.css` `:root` / `:root.dark`。

### 2.1 色彩（浅色默认）

| 用途 | Token | 值 |
|---|---|---|
| 品牌主色 | `--brand` | `#4f46e5` |
| 品牌悬浮 | `--brand-hover` | `#4338ca` |
| 品牌按下 | `--brand-active` | `#3730a3` |
| 品牌浅底 | `--brand-light` | `#eef2ff` |
| 页面底 | `--bg-elevated` | `#f8fafc` |
| 内容面 | `--surface-1` | `#ffffff` |
| 次级面 | `--surface-2` / `--surface-3` | `#f8fafc` / `#f1f5f9` |
| 悬浮 | `--bg-hover` | `#f1f5f9` |
| 边框 | `--border` / `--border-strong` | `#e2e8f0` / `#cbd5e1` |
| 主文 | `--text` | `#0f172a` |
| 次文 | `--text-secondary` | `#334155` |
| 弱文 | `--text-muted` | `#64748b` |
| 成功 | `--success` / `--success-bg` | `#10b981` / `#d1fae5` |
| 警告 | `--warning` / `--warning-bg` | `#f59e0b` / `#fef3c7` |
| 危险 | `--danger` / `--danger-bg` | `#ef4444` / `#fee2e2` |
| 信息 | `--info` / `--info-bg` | `#0ea5e9` / `#e0f2fe` |

暗色下品牌偏 `#6366f1`，表面为深蓝灰（`--surface-1: #131a2d` 等），语义色保留并降低底色透明度。

规则：

- 红 = 错误 / 危险 / 超时 / 破坏性；橙 = 待审批 / 风险复核 / 预算预警。
- 品牌色用于主行动、选中 Tab、焦点环；**不**表达风险等级。
- 主按钮用实体 `--brand`，禁止紫色渐变填充。
- 状态必须配合文字或图标，不能只靠颜色。

### 2.2 SaaS 描边与阴影（现仓主路径）

能力中心 / 运营台优先使用 **ring + elev**，少用硬 `1px` 边框：

| Token | 用途 |
|---|---|
| `--saas-ring` / `--saas-ring-hover` / `--saas-ring-focus` | 表面轮廓与焦点 |
| `--saas-elev-1` / `--saas-elev-2` / `--saas-elev-focus` | 默认 / 悬浮 / 强调抬升 |
| `--saas-divider` | Tab 底部分割线 |

在 `de-employee-page` 内，ring 会混入品牌色（约 14%–40%），形成淡紫描边而非纯灰框。

通用阴影仍保留：`--shadow-xs` → `--shadow-xl`（弹层、下拉等）。

### 2.3 圆角

| Token | 值 | 常用 |
|---|---|---|
| `--radius-sm` | `4px` | 小标签、点状 |
| `--radius-md` | `8px` | 按钮、输入、chip |
| `--radius-lg` | `12px` | 卡片、shell、KPI |
| `--radius-xl` | `16px` | 大弹层（少用） |

### 2.4 字体

| Token | 栈 |
|---|---|
| `--font-sans` | 系统 UI + PingFang SC / Microsoft YaHei |
| `--font-mono` | JetBrains Mono / SF Mono / Consolas（KPI、ID、代码） |

| 层级 | 现仓常见 | 场景 |
|---|---|---|
| 页面标题 | `text-base`–`text-lg`（16–18px），`font-semibold` | 壳内 h1 |
| 区块标题 | `text-sm`（14px），`font-semibold` | section head |
| 正文 | `13–14px` | 表格、描述 |
| 辅助 | `10–12px` | 时间、meta、KPI 标签 |
| 数据 | `18–22px` mono bold | KPI 数值；不宜超过约 `28px` |

## 3. 页面壳层与布局

### 3.1 统一类名（必复用）

| 类名 | 用途 |
|---|---|
| `de-employee-page` | 页面根：背景、内边距、滚动；覆写页内 ring 为品牌色 |
| `de-employee-shell` | 主表面（页头、工作区）；`box-shadow: ring + elev-1`，无硬边框 |
| `de-employee-tabs` / `de-employee-tab` / `.is-active` | 二级导航；激活态底边 `--brand` + 字重 600 |
| `de-employee-icon-tile` | 页头图标底：`--brand-light` + 淡紫描边 |
| `de-employee-btn` / `--primary` | 壳内次级 / 主按钮 |
| `de-employee-chip` / `.is-active` | 筛选胶囊 |
| `de-employee-input` | 输入：品牌 ring；focus 双环 |
| `de-employee-card` | 列表/资产卡；hover `translateY(-1px)` |
| `de-employee-hint` | 提示条浅品牌底 |

页面级 KPI 条命名示例：`home-page__kpis`、`channels-kpis`、`settings-kpis` 等，视觉同构：等高、可点击、左图标右数值。

### 3.2 标准页面骨架

```text
de-employee-page
└─ stack（gap ≈ 12px）
   ├─ de-employee-shell 页头（icon-tile + 标题/副文案 + CTA）
   ├─ de-employee-tabs（控制型模块）
   ├─ KPI 条（运营/能力概览置顶）
   └─ de-employee-shell 主工作区（表 / 卡 / 画布）
```

抽屉、详情、审批按需右侧打开；低频操作进「更多」。

### 3.3 运营总览（现仓特例）

```text
页头 → KPI×6 置顶 → 需要关注 | 投入产出 → 进行中 | 活动 | SLA → 运行细节（默认折叠）
```

- KPI 先于待办；禁止成本等指标在 KPI 与经营区重复。
- Token / P95 / 多序列图表进「运行细节」，不占默认首屏。
- **诚实空态**：无数显示 `0`；无 UsageMeters 计量时成本为 `—`，禁止演示金额填首屏。
- 快捷入口文案「工作伙伴」→ `/partners`；深链可用 `?employeeId=` / `?tab=operations`。
- 类名：`home-page__stack` / `__kpis` / `__mid` / `__attention` / `__roi` / `__workstream`。

### 3.4 专家协作

三栏工作台：会话列表（`copilot-sessions__*`）· 消息流 · 消息上下文 Tab。  
会话项卡片化；搜索/新建按钮用品牌色；上下文 Tab 激活态品牌色，Tab 固定在滚动区外。

### 3.5 平台设置

八 Tab：`tenant | security | backup | apikeys | billing | access | zeroTrust | auditCenter`。  
统一 `settings-*` 壳、KPI、功能卡；访问控制 / 持续验证 / 审计以嵌入子导航呈现。

### 3.6 间距与响应式

- 间距基线：`4 / 8 / 12 / 16 / 20 / 24 / 32`。
- 页内 stack 常用 `gap-3`（12px）；卡片内边距 `14–16px`。
- `≥1200px`：运营 KPI 可 6 列；`≤900px` 双栏改单列；`≤640px` KPI 2 列、面板取消固定高度。

## 4. 组件与反馈

### 4.1 按钮（`@de/web-ui` Button）

- 变体：`primary`（品牌实心）、`secondary`、`ghost` 等。
- 必须具备：默认 / hover / active / focus / disabled / loading。
- 主按钮每区块通常仅一个；危险操作使用明确动词 + 二次确认。
- 悬浮允许 `1px` 上移 + elev 提升；禁用降透明度并保留原因。

### 4.2 Badge / KpiCard

- `Badge` tone：`brand | success | warn | error | info | neutral`。
- `KpiCard`：`compact`（表内）/ `comfortable`（页级摘要）；tone 与图标同色语义。
- 运营首页 KPI 条可用自研 `home-page__kpi`，视觉对齐 channels/settings KPI。

### 4.3 异步与动效

- `<300ms`：按钮 loading；`300ms–2s`：loading + 文案；`>2s`：骨架或进度。
- Toast 短反馈；错误需「重试」且保留输入。
- 过渡 `160–300ms`；尊重 `prefers-reduced-motion`。
- 禁止循环装饰动画；SLA 轮播等可暂停。

### 4.4 弹层与抽屉

- 遮罩半透明；关闭：遮罩 / ESC / 关闭按钮。
- Header / Footer 固定，Body 滚动。
- 抽屉宽：简单详情约 `480px`，复杂配置约 `640px`；小屏全屏。
- 未保存关闭需提示。

## 5. 工作流与 AI 编排（现仓约束摘要）

### 5.1 画布层级

```text
工作流标题
→ 画布 / 模板库 / 执行历史
→ 版本 · 节点库 · AI 辅助 | 保存草稿 · 运行试验 · 更多
→ 画布 + 按需节点抽屉
```

- `AI 辅助` 跳转全屏编排会话 `/workflows/orchestration`，不以画布抽屉完稿。
- 保存草稿为唯一实体主按钮；试运行受校验/策略门禁。

### 5.2 编排会话硬规则

- 澄清可选；生成走工作区允许的模型路由；前端不得伪造成已执行。
- 结果不得自动执行、发布或覆盖当前画布；应用须新 `revisionId`。
- 高风险外部动作须策略、双签、补偿与审计；缺依赖只能隔离草稿。
- 审计不可由用户关闭。

### 5.3 模板库

模板须展示版本、风险、依赖健康；「使用模板」与详情同流程创建草稿，禁止静默覆盖。

## 6. 表单、列表与数据

- Label / 控件 / 帮助文垂直排列；输入高约 `36–40px`。
- Focus：品牌 ring（`de-employee-input` 或等价）；错误在字段下方红字说明。
- 表格：白面、细边/轻 ring、行 hover；风险用 Badge，不用整行高饱和色条。
- 空状态：说明「没有什么 / 为何 / 下一步」+ 一个主行动。
- 加载用骨架或明确文案，禁止空白假死。

## 7. 模块交互边界

| 模块 | 主任务 | 视觉要点 |
|---|---|---|
| 运营总览 | 待处置优先、在岗与诚实 ROI | KPI 置顶；无计量显示 `—`；细节折叠 |

## 8. 可访问性与质量门禁

- 图标按钮具备 `title` 或 `aria-label`。
- 键盘可完成导航、打开、关闭、提交；ESC 关闭最上层弹层。
- 文本对比度达 WCAG AA；状态不只靠颜色。
- 验收八态：默认 / Hover / Active / Focus / Disabled / Loading / Error / Empty。
- 提交前至少：`pnpm --filter web typecheck` · `pnpm --filter web build` · `git diff --check`。
