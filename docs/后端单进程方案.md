# 后端单进程方案（M10 后）

> **版本**：v5.0（2026-10-04）  
> **状态**：**当前阶段（联调 + demo + 单租户开发）默认单进程**  
> **对齐**：[后端架构规划.md](./后端架构规划.md)（逻辑层 Lxx / 模块 Mxx 仍为真相源）  
> **相对 v4.3 修订**：  
> - **qzda-sys / qzda-collab / qzda-cap / qzda-workflow 已折叠到 qzda-app**（M10）  
> - **ServiceMode 收为单一 ModeApp，Domain 收为单一 DomainAll**  
> - **Go 控制面只有一个部署单元**，外加 Python 执行面 3 个 sidecar

---

## 0. 定稿原则

| # | 原则 |
|---|---|
| 1 | **单进程优先**：当前阶段不引入新的 Go 服务；能力进 qzda-app |
| 2 | **逻辑可细、进程要粗**：`platform / policy / audit / collab / cap / workflow` 是模块，不是独立微服务 |
| 3 | **Go 六边形**：单一部署单元内按 Ports & Adapters；模块间禁止跨包直连表 |
| 4 | **Python 执行面独立**：沙箱必须独立端口；agent / rag 按需启 sidecar |
| 5 | **基础服务分目录**：数据、IdP、策略引擎、观测各自可编排 |
| 6 | **永不混部**：`qzda-sandbox` · `qzda-agent-runtime` · `qzda-rag`（执行面互不混） |
| 7 | **Temporal worker 可内嵌**：单进程模式下 `DE_WORKFLOW_WORKER=1` 即在 qzda-app 进程内启动 Temporal worker |

## 1. 部署单元总览（当前阶段）

### 1.0 monolith — 当前唯一形态

**gateway :8089 → qzda-app :8100 + qzda-sandbox :8093**（按需 +qzda-agent-runtime :8091 / +qzda-rag :8092）。`qzda-app` 内含 sys / collab / cap / workflow 全部域逻辑。

| 部署单元 | 端口 | 说明 |
|----------|------|------|
| qzda-gateway | 8089 | Envoy `envoy.monolith.yaml` |
| **qzda-app** | **8100** | **单进程 monolith**（`ModeApp` / `DomainAll`） |
| qzda-sandbox | 8093 | 技能沙箱（必须独立） |
| qzda-agent-runtime | 8091 | Python sidecar，按需 |
| qzda-rag | 8092 | Python sidecar，按需 |
| Temporal worker | (qzda-app 进程内) | `DE_WORKFLOW_WORKER=1 DE_TEMPORAL_HOST=...` 时启动 |

启动：`make compose-up-monolith` / `make run` / `scripts/dev-stack/run-stack.sh`。

### 1.1 进程内组成

`qzda-app` 单进程内同时挂载：

| 子模块 | 范围 |
|--------|------|
| **sys** | platform / ops / 设置 / policy / audit |
| **collab** | session / task / 审核 / 流式回合 |
| **employee** | 岗位 / 装配 / 上岗 |
| **cap** | model / knowledge / memory / skill 清单 / channel |
| **workflow** | 流程版本 / 试运行（HTTP） |
| **workflow Temporal worker** | 可选进程内 goroutine（`DE_WORKFLOW_WORKER=1`） |

所有 collection 由 `DomainAll` 单一写域拥有；`CanWrite(collection)` 永远返回 true；`ownsCollabRuntime()` / `ownsCapRuntime()` 永远返回 true。

### 1.2 未来切分路径（仅记录，按需触发）

下列拆分 **不再自动发生**，仅当业务规模 / 团队边界 / 故障隔离需求触发时手动执行：

| 触发条件 | 拆出动作 |
|----------|----------|
| 政策 / 审计读写压力大、需独立 RBAC | 拆 `qzda-policy` / `qzda-audit` 二进制（M10 已并回，不再） |
| workflow 编排延迟抖动 | 把 Temporal worker 拆出到独立 `qzda-workflow` 二进制 |
| Python Harness 远程化需要常驻进程 | `qzda-agent-runtime` 必起，`DE_RUNTIME_MODE=remote` |
| 沙箱执行排队 / 资源占用上升 | 把 `qzda-sandbox` 横向扩多实例 |

每次拆分复用同套六边形包：`internal/server` → `internal/{platform,policy,audit,collab,cap,workflow}`，handler 不改、契约不变。

| 维度 | v4.3（coarse） | v5.0（monolith） |

## 3. 演进护栏

- **不引入新的 Go 服务**：扩展能力时只在 `qzda-app` 内加 handler / service。  
- **不恢复微服务路径**：除非触发条件 §1.2 中明列。  
- **保持单进程边界**：所有 collection 由单一写域拥有；handler 跨域调用走函数调用，不走 HTTP。  
- **保留六边形结构**：未来真要拆，模块目录已经按能力分包 (`internal/platform` / `internal/policy` / ...)，迁包成本低。
