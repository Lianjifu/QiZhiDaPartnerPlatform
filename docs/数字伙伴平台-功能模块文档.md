## 2. M01 · 运营总览

**功能：** 平台总览仪表盘；展示与实体数据同源的直播聚合，不作演示数字充数。

### 当前实现

- KPI / 需关注 / 团队动态：以 `/api/digital-employees`、`/api/tasks` 等实体为准；`/api/home/kpis` 仅作 parity，不驱动主 KPI
- `/api/home/extra`、`/api/operations/overview`：`live-aggregate`（后端 `ops_aggregate`）；空工作区为 0 / 空列表
- 成本卡片：仅当计量来源为 `usage-meters` 时展示金额，否则 `—` /「暂无计量」
- 快捷入口：「数字伙伴」→ `/partners`；健康度深链 `/partners?tab=operations`；员工深链 `?employeeId=`

### 目标能力

- 持久 UsageMeters / Prometheus 刷新
- 异常红色高亮与健康度评分（有计量后）

### 依赖

- 任务中心、数字伙伴运行态、模型用量、合规/审计摘要

## 3. M02 · 专家协作

**功能：** 与已上岗数字伙伴协同处置；会话、工具、证据、审批与审计一体化。

### 当前实现

| 区域 | 能力 |
|---|---|
| 左栏会话记录 | 置顶/今天/更早分组；新会话；搜索；激活态与专家标签；删除走 `PersistDeleteSync`（含 messages / snapshots） |
| Composer | 产品层运行档：问答 / 方案 / 执行；推理档位（省 / 标准 / 深）；上下文占用；附件 / @ / 命令插入 |
| 中栏对话 | 消息流、ThoughtPanel、工作卡、工具调用、流式状态、人工交接、导出 |
| 右栏上下文 | 概览处置状态与治理 KPI；证据/任务/审批/审计 Tab；RAG 指标；岗位专家绑定 |
| 安全 | 生产写操作身份绑定受控双签；风险等级展示；管理员上岗/上架可自批，普通用户须审批 |

### 目标后端分工

| 层级 | 技术 |
|---|---|
| 对话路由、上下文、计费、双签校验 | Go |
| Agent 执行、RAG、工具/Skill 调用 | Python（LangGraph） |

### 核心特性

- 切换/绑定在岗岗位专家（非自由「市场试用」为主路径）
- 产品档位映射 ABI：问答/方案 → `investigate`，执行 → `execute`（写操作受策略与审核）
- 消息级可追溯：证据引用、关联任务、审批队列、审计流水
- 写动作二次确认 + 双签门禁
- 对话与工具调用写入审计关联 ID

### 依赖

- 强依赖：数字伙伴、知识、技能、模型路由  
- 联动：任务中心、消息渠道、持续验证、审计中心

## 6. M05 · 数字伙伴

**功能：** 以**岗位**为边界的数字伙伴全生命周期：配置 → 能力装配 → 评测上岗 → 运行运营 → 证据。

**页面路由：** 仅 `/partners`（组件 `DigitalEmployees.tsx`）。侧栏文案 user/admin 为 **数字伙伴**，auditor 为 **伙伴档案**。

### 当前实现（主 Tab）

| Tab key | 中文 | 能力 |
|---|---|---|
| `catalog` | 专家目录 | 在岗/待上岗筛选、岗位与风险标签、岗位蓝图创建；含出厂 **办公助手** `de-office` |
| `roleSetup` | 岗位配置 | 档案、职责边界、人工接管与记忆策略契约 |
| `capabilities` | 能力装配 | 仅可选各能力中心**已准入/已发布**资产 |
| `release` | 上岗发布 | 评测门禁、双重审批、完整性检查 |
| `operations` | 运行管理 | 运行健康、交接与例外处置 |

### 深链与 API

| 项 | 约定 |
|---|---|
| 选中伙伴 | `?employeeId=` 或兼容 `?id=` |
| 切 Tab | `?tab=catalog\|roleSetup\|capabilities\|release\|operations` |
| 主 API | `/api/digital-employees` · `/overview` · `lifecycle` / `release` / `evaluate` / `configuration` / `evidence` … |
| 遗留 | `/api/agents*` 只读投影，前端主路径不依赖 |

### 核心原则

- 底层 Agent 为执行内核，由数字伙伴引用，不作侧栏一级「市场」主入口
- 模型/知识/技能/工作流/渠道仍由各自控制面发布；数字伙伴只引用版本并留存装配证据
- 长期记忆只形成知识候选，不直通权威知识

### 目标后端

- Go：生命周期状态机、发布门禁、权限（本仓 **qzda-app** monolith 已联调）  
- Python：评测与运行时 Agent 内核

### 依赖

- 能力：模型、知识、技能、记忆、工作流、渠道  
- 治理：访问控制（发布审批）、持续验证、审计

### 岗位包与平台工具

| 类型 | 说明 |
|------|------|

| Tool | 工单/CMDB/通知等业务工具 |

| 访问策略 | 启用/停用（基线不可停）、版本 |
| 临时授权 | 授予/回收、到期失效 |
| 策略事件 | 命中说明与下一步指引 |

### 决策枚举

`allow` · `mask` · `approval_required` · `deny`

## 17. 跨模块关键流程（对齐实现）

### 流程 A：专家协作处置（控制面）

```text
专家协作发问
  → 绑定在岗数字伙伴
  → 模型路由 + 知识/记忆检索
  → 技能/工具调用（策略评估）
  → 写操作：双签 + 持续验证
  → 任务中心跟进（可选）
  → 消息渠道通知（可选）
  → 审计中心关联 ID
```

### 流程 B：数字伙伴上岗

```text
岗位配置 → 能力装配（仅已发布资产）
  → 评测门禁 → 发布审批（访问控制）
  → 上岗运行 → 运行管理 / 记忆沉淀
  → 知识候选 → 知识中心审核入库
```

### 流程 C：渠道告警闭环（目标语义）

```text
消息渠道收告警 → 任务中心建单
  → 工作流/数字伙伴处置
  → 双签变更 → 渠道回执 → 审计
```
