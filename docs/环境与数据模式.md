# 环境与数据模式：演示环境 vs 生产环境

## 总开关

`DE_ENV` = `demo` | `development` | `staging` | `production`

| 对外 | `DE_ENV` | 数据 | Persist | 演示 Token |
|------|----------|------|---------|------------|
| **演示环境** | `demo`（别名 `mock`） | ACME seed，仅内存 | 否 | 允许 |
| **本机联调** | `development`（默认） | 空库启动，PG hydrate | 是 | 默认禁止 |
| **预发** | `staging` | 同生产规则 | 是 | 禁止 |
| **生产** | `production` | 同生产规则 | 是 | 禁止 |

`DE_BAN_MOCK_TOKEN` / `DE_BAN_DEMO_TOKEN` **只**禁止演示 token，**不再**触发双人审批。双人审批仅 `staging|production`。

本机 LaunchAgent（`scripts/dev-stack/run-stack.sh`）默认：

```bash
DE_ENV=development
DE_BAN_MOCK_TOKEN=1
```

联调若需 mock token，显式设 `DE_ALLOW_DEMO_TOKEN=1` 或 `DE_BAN_MOCK_TOKEN=0`。

## Postgres 只使用 Docker

本机联调 **禁止** 再跑 Homebrew / 本机 Postgres。`DE_DATABASE_URL` 的 `127.0.0.1:5432` 必须指向 Compose 服务 `qzda-postgres`（镜像 `postgres:16-alpine`）。

若本机曾安装 `postgresql@17` 等并监听 `127.0.0.1:5432`，会抢掉 Colima 端口映射，导致 qzda-app 连到错误的库。启动前执行：

```bash
bash scripts/dev-stack/ensure-docker-postgres.sh
# 或
cd backend && make infra-env
```

脚本会停掉占用 5432 的 Homebrew Postgres，拉起 `qzda-postgres`，并校验版本为 16.x。

## 空库不再灌演示 seed

`apprun` 在非 `demo` 模式下使用 `store.NewEmpty()`，**禁止**「空库 PersistNow(seed)」。启动时仅：

- hydrate 已有 PG 行
- **确保稳定壳工作区 `w1`（名称「默认工作区」）存在**：即使库里已有用户自建工作区（如 `workspace-1`），仍会补齐 `w1`；并按 owner/成员重建内存访问授权，避免重启后列表被 JWT 固定 `w1–w4` 滤空
- 确保 builtin 技能目录 + **各工作区** `autoInstall` 岗位包（含 `general` / `office`）（`EnsureBuiltinSkillsReady`）
- 确保办公开箱知识包 published（`EnsureBuiltinKnowledgeReady`）
- 确保出厂流程模板（办公 Certified + 部门审批 + 高级库）（`EnsureBuiltinWorkflowsReady`）；个人模板 `wft-user-*` 不覆盖
- 可选 `DE_ENSURE_GENERAL=1` 时补通用员工；办公助手 `de-office` 随通用伙伴路径写入

### 硬删除必须 PersistDelete

多数集合是 **Upsert**，只改内存切片再 `Persist` **不会**删掉 PG 旧行。会话/知识/模型供应商/渠道部署/技能卸载/个人流程模板（`workflow_templates`）等硬删路径需调用 `PersistDelete` / `PersistDeleteSync`（kernel 表走 `KernelStore.DeleteMany`）。记忆记录当前为软删（`status=revoked`）。覆盖矩阵见 [审计-硬删PersistDelete覆盖.md](./审计-硬删PersistDelete覆盖.md)。

环缓冲裁剪（`context_snapshots`、`channel_inbound`）亦需对被挤出 id 调删除。

### 工作区 Header 不可伪造

`x-workspace-id` 只能在身份已绑定成员集合内选择；显式传入未授权工作区返回 **403** `E_WORKSPACE_SCOPE`（空 Header 则回落默认/首选工作区）。三层作用域目标模型见 [ADR-014](./adr/ADR-014-scope-layers.md)。

### 为何联调时仍看到「演示 + 生产」混在一起？

常见误判有两类：

1. **Network 里同一接口出现两次**  
   React `StrictMode`（开发态）会故意双挂载，导致 `useApiQuery` 打两遍**同一个**真实网关。这不是「演示接口 + 生产接口」两套来源。前端 `VITE_USE_DEMO/MOCK=false` 时只会走 gateway。

2. **单个接口响应里既有 ACME seed 又有真实数据**  
   历史版本曾用 `NewDemo()` + Persist 把演示数据写进 Postgres。切到 `development` 后只是不再**新灌** seed，但 **hydrate 会把库里已有行全部读回**。

清理残留（含联调会话/记忆等第二阶段清空；保留模型供应商与工作区壳）：

```bash
psql "$DE_DATABASE_URL" -f backend/scripts/purge-demo-seed-ids.sql
# 或 make db-reset-dev（危险：丢全部数据）
cd backend && make build
launchctl kickstart -k "gui/$(id -u)/com.qizhida.dev-stack"
```

## 审批（上架 / 上岗 / 发布）

| 角色 | 行为 |
|------|------|
| **管理员** | 申请可直接生效，可自批；高风险也可跳过会签 |
| **普通用户** | 须审批；申请人不可自批；高风险需管理员首批 + 另一管理员会签 |

覆盖：上岗、路由、知识、流程技能、技能目录晋升、备份等（见 `dual_approval.go`）。

## 技能岗位包与平台工具

| 概念 | 说明 |
|------|------|
| **平台工具** | `manifest.platformTools`（如 `knowledge.retrieve`）；Go Harness **内置**，冷启动即用，**无需岗位包安装** |
| **通用岗位包** | 冷启动自动装到各工作区（weather / docx / …） |
| **办公岗位包** | 冷启动自动装 `office`（summarize/docx/pdf/pptx/spreadsheets/diagram-maker） |
| **协作扩展 / 重依赖 / 全量** | 按需 `POST /api/skills/apply-pack/:id` 装到**当前工作区**；重依赖须审批单号 |

`GET /api/skills/packs` 按工作区返回 `installed` / `installedCount` / `missingSkills`，并附带 `platformTools` 清单。前端「平台工具 → 岗位包」据此显示「已安装」而非仅 toast。

## 办公开箱三件套

| 资产 | 路径 | 说明 |
|------|------|------|
| 知识包 | `backend/builtin/knowledge/office/` | `kp.office.handbook` 等 6 包，冷启动写入并 published |
| 流程模板 | `backend/builtin/workflows/` | `wf.office.*`（部门键 `office`）+ 部门审批 Certified + IT 高级库 |
| 场景三联 | `backend/builtin/scenarios/office/manifest.json` | 知识 · 技能 · 流程 ID 绑定 |
| 办公助手 | store 内置伙伴 `de-office` | 装配办公知识/技能，可在专家协作选用 |

控制台「工作流程 → 流程模板」：

- **平台内置 / 个人创建** 分栏；个人模板支持存为模板与删除（`wft-user-*`）
- 部门筛默认 **办公通用**；选「全部」时统一平铺 + 分页（不再按部门分组表头）
- 模板卡片可展示配套知识/技能标签（来自场景三联）

## 前端

- `VITE_USE_DEMO=true`（兼容 `VITE_USE_MOCK=true`）：本地演示 Handler
- 默认 `false`：打真实网关（同源 `/api` → Vite proxy → `:8089`）
