## 五、Gap 与风险

### G1 · `handlers_models.go` 1269L 单文件迁移

1269L 是迄今 backend 单文件最大段(超过 M06 `builtin_workflows.go` 433L 的 3 倍)。

**Why:** provider CRUD + routing + governance + audit 都混在同文件,无清晰分段
**How:** 拆为 `handlers.go` (≤700L, provider + aliases)+ `handlers_routing.go` (~400L, routing + failover)+ `handlers_governance.go` (~300L, governance + audit)。**本方案暂列单文件,实际执行时视代码分段细密度决定**。

### G2 · SSE streaming 测试 (`modelInvokeStream`)

SSE 不同于普通 JSON 响应,需断言 `text/event-stream` Content-Type + 多 chunk 解析。

**Why:** 测试基础设施需扩展
**How:** P3 用 `bufio.Scanner` 读取 httptest.Response.Body,断言每个 chunk 以 `data: ` 前缀且 JSON parse 通过。

### G3 · 反向 import `model_invoke → copilot.ResolvedTurn`

迁完后 `internal/models/` 直接 import `internal/copilot/` 拿类型(单向,无循环)。

**Why:** copilot 是 ResolvedTurn 的"语义所有者",迁移后 models 是消费者
**How:** D5 默认方案 A — 在 `internal/copilot/service.go` 加 `ResolvedTurn` 类型 export,`internal/models/handlers_invoke.go` 直接用 `copilot.ResolvedTurn`(同 M03 `internal/tasks` import copilot 拿类型同模式)。

### G4 · `handlers_c.go` M08 aliases 散落

`handlers_c.go` 1365L 含 M03/M05/M08 多个模块代码;M08 段 L75-139 仅 65L。

**Why:** 跨模块混居文件,删除 M08 段不能影响 M03/M05
**How:** P2 把 L75-139 迁到 `internal/models/handlers.go` alias 段;`handlers_c.go` 删除 M08 段后保留 M03/M05 段,继续在 server/。

### G5 · `internal/modelprov/` 子包边界

modelprov 是 LLM 协议适配层,被 `internal/copilot/`、`internal/selfimproving/`、`internal/models/`(本次迁入)三处直接 import。

**Why:** 子包独立性必须保持
**How:** `internal/models/` 通过 Deps 注入 `modelprov.Client`(而非在 service.go 内部 import),便于测试时换 mock client。

### G6 · M02 copilot → M08 跨模块入口(已有)

`server.StreamLLMForCopilotFn` 在 copilot Deps 中是函数值。

**Why:** 跨包依赖 decoupling
**How:** P2 后 `internal/copilot/service.go` 中 `Deps.StreamLLMForCopilot = s.modelSvc.StreamLLMForCopilot`(`buildModelSvc` 注入)。
