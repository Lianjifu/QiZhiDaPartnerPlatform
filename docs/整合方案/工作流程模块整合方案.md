## 一、背景与目标

### 1.1 背景

M06 工作流程(Workflow)是平台的流程化运营载体:支持模板编排、运行编排、技能发布、运行审计。引擎层已抽到 `qzdaworkflow/` 包(Temporal 形态本地实现),但 handler + 胶水层仍在 `internal/server/` 散落,且前端 `pages/Workflows.tsx` 单文件 **4479L** 是项目迄今最大 TSX。

代码当前形态:

- **前端**:
  - `pages/Workflows.tsx` 单文件 **4479L**(**11× 超 400L TSX 门禁,迄今最严重**)
  - `pages/WorkflowOrchestrationSession.tsx` **1057L**(2.6× 超)
  - `pages/workflows.copy.test.ts` 189L
  - `features/workflows/{version-diff, department-templates}.ts` + 各自测试(已存在薄层,扩展即可)
- **后端**:
  - **引擎包** `internal/qzdaworkflow/`(326 LOC,4 文件):`engine.go` 129L / `activities.go` 87L / `temporal.go` 86L / `engine_test.go` 24L — **自包含,本次不动**
  - **handler + 胶水**(全在 `internal/server/`):
    - `handlers_d.go` 386L — `listWorkflows` / `createWorkflow` / `listWorkflowSkills` / `listWorkflowRuns` / `runWorkflow`
    - `workflow_skill.go` 126L — `publishWorkflowAsSkillLocked` / `syncWorkflowSkillCatalogLocked` / `enableWorkflowSkillCatalogLocked`
    - `builtin_workflows.go` 433L — `listWorkflowTemplates` / `createWorkflowTemplate` / `deleteWorkflowTemplate` / `workflowTemplateOrigin`
    - `handlers_p1.go` L211 — `listWorkflowGenerations`
    - `handlers_skills.go` L1786 — `publishWorkflowSkill`
    - `handlers_skills_detail.go` L391 — `bindWorkflowCapability`
- **Connect-RPC**:无 — 纯 HTTP 模块
- **微服务**:`qzda-workflow` 命名保留,本次不抽

`internal/server/server.go` 中 M06 路由 **13 条**(L888-L914):

### 1.2 目标

- **前端**:`grep frontend/web/src/features/workflows/` 找全所有 M06 代码;每个 TSX ≤400L

## 五、Gap 与风险

### G1 · `Workflows.tsx` 4479L 拆分对 diff 的影响

11× 超门禁;Section 边界识别需模板依赖。

**Why:** 项目迄今最大 TSX,视觉搜索成本极高
**How:** 按 tab 切分(列表/编辑/运行/技能/设置/生成),每段 ~350L

### G2 · 引擎 `qzdaworkflow/` 与 handler `internal/workflows/` 双包命名

`qzdaworkflow` 是引擎(Temporal 形态),`workflows` 是 HTTP handler。命名混淆风险。

**Why:** 两个 M06 命名空间并存
**How:** P2 阶段在 `internal/workflows/service.go` 顶部加 package doc 明确二者边界(`qzdaworkflow = 引擎,internal/workflows = HTTP handler + 业务胶水`)

### G3 · `WorkflowOrchestrationSession.tsx` 拆分与 `Workflows.tsx` 子组件复用

Orchestration 页面与 Workflows 列表的 `WorkflowsTab.Detail` 可能复用部分渲染逻辑。

**Why:** 避免重复 JSX
**How:** 抽到 `WorkflowsShared.tsx`,两个 page 都引用

### G4 · 散落函数内联后 server/ 文件结构

`handlers_p1.go` L211 / `handlers_skills.go` L1786 / `handlers_skills_detail.go` L391 删除后,这些 server/ 文件保留?还是清理?

**Why:** 删函数后文件是否仍工作?
**How:** 删后跑 `go build` 验证;若文件空/残余引用,清掉(类似 M05 P2 的 `handlers_capability_catalog.go` 整文件删除)

### G5 · `runWorkflow` 调 `qzdaworkflow.Engine.StartTrial` 的依赖注入

`runWorkflow` handler 需要 `Engine` 实例。当前 handler 通过 `s.something` 调用。

**Why:** 跨包依赖不能 import server
**How:** `Deps` 加 `StartTrial func(...)` 函数值,`buildWorkflowSvc` 注入 adapter
