## 一、背景与目标

### 1.1 背景

M08 消息渠道 是平台把"内部 copilot 输出"对接到外部 IM(飞书 / 企微 / 钉钉 / 自定义 webhook)的统一控制面。包含 IM 部署管理、投递策略(primary + fallback 路由 + 重试 + 限速)、模板与黑名单、运行健康、失败死信与回放、审计、IM 平台事件回调。

代码当前形态:

- **前端**:`pages/Channels.tsx` 单文件 **1455L**(3.6× 超 400L TSX 门禁,**必须拆**);`features/channels/channel-ui.ts` 60L + test 50L 已有,但仅 helpers(连接模式归一化、入站形态判定、删除动作文案);主页面未拆分。
- **后端**:`backend/internal/server/` 中:
  - `handlers_channels.go` **1496L**(超 600L TS 门禁,2.5×,**必须拆**)
  - `handlers_channel_webhooks.go` 218L(单文件 OK,做对外 IM 事件回调)
  - `handlers_channels_test.go` 244L
  - `handlers_channels_enterprise_test.go` 100L
  - `handlers_channels_feishu_test.go` 168L
- **路由**:`server.go:1205-1255` 共 **25 个 case** 散在一个巨型 switch 段,集中在 M08
- **微服务**:无;`internal/server/` 是单进程入口
- **跨包调用**:无强跨包耦合(不依赖 memory / knowledge / copilot 内部数据);vault 解密 + audit append + persist 通过 server 包注入

`internal/server/server.go` 中 M08 路由 **25 条**:

### 3.2 关键合约

#### Service 形态

```go
package channels

type Service struct {
    Deps
    Store *store.Store
}

type Deps struct {
    WorkspaceID       func(*http.Request) string
    IdentityFrom      func(context.Context) *auth.Identity
    DecodeMap         func(*http.Request) (map[string]any, error)
    EvaluateZeroTrust func(id *auth.Identity, resource, action, classification string, external bool, corr string) (map[string]any, error)

    // Vault 解密 + 凭据构造(跨模块,留在 server 包)
    ResolveVault func(r *http.Request, credRef string) string

    // 审计 + 持久化(沿用 memory 模式)
    AppendChannelAuditLocked func(ws, actor, action, target, result, reason, corr string)
    PersistChannel           func()
}

// NewService builds a Service. store is required; deps may be partial for tests.
func NewService(store *store.Store, deps Deps) *Service { ... }
```

## 六、关键决策点

| 决策 | 默认选择 | 理由 |
|---|---|---|
| 是否抽 useChannelsController hook? | **不抽** | 1455L 主要被 6 tab 平分,各 tab 内部状态自洽;P3 用组件级测试即可 |
