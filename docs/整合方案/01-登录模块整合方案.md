# 登录模块整合方案

> 状态:**方案稿,未执行** · 适用范围:QiZhiDaPartnerPlatform 登录域(密码登录 + OIDC 登录 + 登出)
> 最近更新:2026-10-01

---

## 一、背景与目标

### 1.1 背景

登录相关代码当前散落在多个目录:

- **前端**:`pages/`、`router/`、`stores/`、`layouts/`、`lib/`、`packages/api/` 都有登录相关逻辑
- **后端**:HTTP 处理器在 `internal/server/`,但 JWT / OIDC 库又在 `internal/auth/` —— 同一个登录域在两个目录之间来回跳

新人找"登录代码在哪"需要跨多个目录才能拼出全貌。

### 1.2 目标

- **前端**:`grep frontend/web/src/auth/` 能找全所有登录域代码
- **后端**:`grep backend/internal/auth/` 能找全所有登录域代码
- **行为零变化**:JWT、Mock token、路由路径、localStorage key、env 变量全部保留
- **为未来抽微服务铺路**:`auth/` 自包含,不依赖 `*Server`

### 1.3 不在范围内

| 项 | 说明 |
|---|---|
| 新增后端 logout 端点 | 当前不存在,整合后仍不存在(见 §七) |
| JWT 黑名单 / refresh token | 单独排期 |
| httpOnly cookie 替换 localStorage | 单独排期 |
| 沙箱 runtoken 整合 | 不属于用户登录域,保持独立 |
| `App.tsx` 路由权限列表重构 | 可选,本方案不包 |

## 三、原则

| 原则 | 含义 |
|---|---|
| 重排优先于重写 | 只搬迁 + 改 import,不改 JWT、路由、Mock token 名、存储位置 |
| 行为契约冻结 | 整合前后任何行为差异必须显式列出并经评审 |
| 避免循环依赖 | `auth/` 不依赖 `stores/`、`auth/` 不依赖 `*Server` |
| 文件大小门禁 | pages ≤50L / TSX ≤400L / TS ≤600L(见 `w4_a_collection_complete` memory) |
| 跨域引用最小化 | 搬动登录代码后,跨域引用变更控制在必要范围内 |

### 4.3 关键决策

- **不建 `auth/store/` 子目录**:`authStore.ts` 留在 `stores/`,仅在 `auth/index.ts` `re-export`。理由:`stores/` 是 Zustand 容器通用机制目录,被 workspace header、ApiClient、ProtectedRoute、AppLayout 跨域引用;搬走扩散 import 范围超出"登录整合"。
- **`services/query.ts` 不动**:TanStack Query 泛型包装,不识别登录态,被全应用复用。
- **`lib/workspace-header.ts` 不动**:读的是 workspace 成员,不是 token。
- **`lib/api-mode.ts` 不动**:demo 模式开关,与登录流程解耦。
- **`router/` 目录搬空后删除**:避免两个守卫目录歧义。
- **`packages/api/src/index.ts` 不动**:它通过 getter 间接读 token,自己零登录代码。

### 4.4 `useLogout` 设计

```ts
// auth/hooks/useLogout.ts
export function useLogout() {
  const navigate = useNavigate();
  return useCallback((opts?: { from?: 'menu' | 'reauth' | 'expired'; notify?: string }) => {
    useAuthStore.getState().logout();          // 清 localStorage.token + Zustand state
    queryClient.clear();                        // 清 TanStack Query 缓存
    if (opts?.notify) toast.info(opts.notify);
    if (location.pathname !== '/login') navigate('/login', { replace: true });
  }, [navigate]);
}
```

> **清 TanStack Query 缓存是新增项**。当前 `authStore.logout()` 只清 token,不清 query 缓存,切账号时会泄漏前一个用户的工作区数据。代价极小,建议加;若要求"纯重排零行为变化",去掉。

### 5.3 `auth.Handler` 接口设计

```go
// auth/http.go
type Handler struct {
    Sign               func(ttl time.Duration) (string, error)  // 实际是 auth.Sign
    Parse              func(token string) (*Identity, error)
    OIDC               *OIDC
    ForceOIDCLogin     func() bool
    AllowPasswordLogin func() bool
    AllowMockIdentity  func() bool
    AuditSink          func(ctx context.Context, action string, actor *Identity)
}

func (h *Handler) Login(w http.ResponseWriter, r *http.Request)        { ... }
func (h *Handler) OIDCLogin(w http.ResponseWriter, r *http.Request)   { ... }
func (h *Handler) OIDCCallback(w http.ResponseWriter, r *http.Request) { ... }

func (h *Handler) Routes() []Route {
    return []Route{
        {Method: "POST", Path: "/api/auth/login", Handler: h.Login},
        {Method: "GET",  Path: "/api/auth/oidc/login", Handler: h.OIDCLogin},
        {Method: "GET",  Path: "/api/auth/oidc/callback", Handler: h.OIDCCallback},
    }
}
```

设计要点:

- `Handler` 不依赖 `*Server`,后续抽微服务直接拔
- `Sign` / `Parse` 走函数注入,避免 `auth/http.go` 与 `auth/jwt.go` 强耦合
- `AuditSink` 注入,避免 `auth/` 反向依赖 server
- `Routes()` 输出固定顺序,server 注册时按顺序追加,保证路由行为不变

### 5.4 各文件改动要点

**`auth/http.go`**(新建) — 三个方法:

- `Login`:从 `server.go:1155-1198` 搬入,语义完全保留(force OIDC / ban mock / mock token 分支)

## 八、已知 Gap(整合后保留,不修)

| Gap | 当前行为 | 风险 |
|---|---|---|
| **无服务端 logout** | 客户端清 localStorage 即"登出",token 在 24h 内仍可被复用 | 共享设备 / token 泄露场景下无服务端失效 |
| **JWT 无黑名单 / refresh** | 24h TTL 到期才失效 | 短期无法撤销 |
| **logout 不发请求** | 没有"审计登出"事件 | 行为追踪缺口 |
| **登出后旧 token 仍能"复活"** | 客户端清掉,但若有人重新塞回 localStorage,后端仍接受 | 见 L4 |
| **无密码哈希** | `s.login` 仅根据 email 经 `auth.RoleFromEmail` 推角色,密码未与任何存储对照 | 当前为 dev-only Mock,目标生产用 Authentik OIDC |
| **OIDC dev-code 回退** | `QZDA_OIDC_ISSUER` 未配置时,`oidcCallback` 接受 `code=admin|user|audit` | 仅供本地演示,生产必须配置 OIDC issuer |

修这些要单独排期:**httpOnly cookie + 服务端 session 表 + 登出审计 + 密码哈希**。本次只重排不修。

## 九、决策点(已确认 2026-10-01)

| # | 决策 | 默认决定 | 影响 |
|---|---|---|---|
| 1 | `useLogout` 是否清空 TanStack Query 缓存? | ✅ 是 | 避免切账号脏数据;代价小 |
| 2 | `auth.Handler` 是否用函数注入(`Sign func(...)`)? | ✅ 是 | 便于后续抽微服务 |
| 3 | `permissions.go` 是否从 `jwt.go` 拆出? | ✅ 是,P2 末尾做 | 单一职责 |
| 4 | `router/` 目录搬空后是否删除? | ✅ 是 | 避免两个守卫目录 |
| 5 | `LoginRequest` / `LoginResponse` 类型是否现在补? | ✅ 是 | P1 建 `packages/types/src/auth.ts`;后端 Go struct 同步 |
| 6 | `App.tsx` 路由权限列表是否抽到 `auth/guards/routePermissions.ts`? | ❌ 否 | 留作可选,本方案不包 |
| 7 | `auth/middleware.go` 是否预留 `OnLogout` 钩子? | ❌ 否 | YAGNI |
| 8 | 联测是否包含 L4(旧 token 复活)作为已知 gap 文档? | ✅ 是 | 用作防回归标记 |
