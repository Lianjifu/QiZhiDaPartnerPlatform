## 一、背景与目标

### 1.1 背景

M09 技能中心是平台的"可复用执行能力"层:技能目录、导入/打包、依赖矩阵、签名/校验、运行时 sandbox、子智能体绑定、治理与审计。承载 M02 copilot 内置技能加载、M06 工作流程发布技能、M05 数字伙伴给智能体绑技能等多处依赖。

代码当前形态(**迄今最大模块,9K LOC 后端**):

- **前端**:
  - `pages/Skills.tsx` 单文件 **1584L**(3.96× 超 400L TSX 门禁,接近 M07 `Knowledge.tsx` 1298L)
  - `features/skills/` 已存在 7 个 feature 文件(治理/集成/打包/平台工具/模态/共享)共 ~1900 LOC
  - 无 `pages/SkillPackages.tsx` / `pages/Sandbox.tsx` — 全部归在 `/skills` 一站
- **后端**(全在 `internal/server/`,17 个文件 ~9000 LOC):
  - `handlers_skills.go` **1748L** — 列表/导入/打包/治理/审计/执行/apply-pack 主体
  - `handlers_skills_detail.go` 390L — `/api/skills/{id}/*` catch-all(per-resource 子 action)
  - `handlers_skills_catalog.go` 402L — 目录发布/同步
  - `handlers_skills_package.go` 395L — 打包导入 vetter 接线
  - `handlers_skills_policy.go` 266L — 策略评估
  - `skill_artifacts.go` **1410L** — PPTX/DOCX 生成(调 `services/qzda-sandbox/scripts/*`)
  - `skill_artifacts_office.go` 485L — PDF 生成
  - `skill_artifacts_pptx_preview.go` 492L — PPTX 预览
  - `skill_artifacts_pptx_validate.go` 77L — PPTX 校验
  - `skill_harness.go` 672L — runtime subprocess 接线(`SandboxID:"sandbox"` L596)
  - `skill_turn.go` 461L — turn 编排
  - `skill_turn_office.go` 460L — Office turn

### 1.2 目标

- **前端**:`grep frontend/web/src/features/skills/` 找全所有 M09 代码;`SkillsPage` ≤400L(shell),tab 子组件 ≤400L
- **后端**:`grep backend/internal/skills/` 找全 M09 handler + 业务 + 签名接入 + runtime;4 子包维持独立
- **行为零变化**:20 路由 + 4 子包 vetter + ed25519 签名 + Python sandbox subprocess 全部保留
- **包边界真实**:`internal/skills/` 自包含,只依赖 `internal/auth` / `internal/policy` / `internal/store` / `internal/skills/{registry,manifest,policy,vetter}` / `services/qzda-sandbox/signing` / `pkg/errors`
- **拆 `handlers_skills.go` 1748L** + `skill_artifacts*.go` 2464L + `skill_turn*.go` 921L:按主题分多文件
- **抽 `Service` struct + Deps**:替代 `*Server` 直调;sandbox 客户端、signer、builtin loader 通过 Deps 注入

## 五、Gap 与风险

### G1 · 17 个后端文件 9K LOC 整体迁移

17 个文件共 ~9000 LOC,是迄今最大单模块迁移(M07 4 文件 2.5K,M08 4 文件 2.2K)。

**Why:** 单文件超门禁多 + M09 模块归属
**How:** 按主题拆 18 文件(主体) + 4 子包 + artifacts 子包,每个文件 ≤600L;`internal/server/skills_compat.go` 渐进删除。

### G2 · `.signed` skill verification(Phase 4 gap)

`handlers_skills_detail.go` + `skill_signature_policy.go`(59L)gate signed/unsigned;unsigned 走 `sc-unsigned` mock。

**Why:** Phase 4 gap fix 是 `.signed` skill 校验逻辑补全
**How:** 本方案不增强校验逻辑,签名 gate 整体迁 `internal/skills/signature_policy.go`,后续单独 ticket 补 `.signed` 校验路径。

### G3 · Python sandbox subprocess 跨进程边界

`skill_harness.go:596` 的 `SandboxID:"sandbox"` 是 Python runtime subprocess 调用点;`services/qzda-sandbox/main.py` 是 Python 入口。

**Why:** Go ↔ Python 跨语言,subprocess 模型
**How:** `internal/skills/harness_sandbox.go` 抽象 `HarnessClient` interface,production 用 subprocess client,test 用 mock client;P3 S11 走 mock harness。

### G4 · 路径硬编码(`../../services/qzda-sandbox/builtin/skills/...`)

`server/skill_artifacts*.go:90,96,542,556,675` + `copilot/skill_artifacts_helpers.go:679,684` 硬编码相对路径。

**Why:** 相对路径基于 git 根,迁完路径稳定
**How:** P2 阶段跑 `go build` + 单测验证路径解析;若失败,改成 `filepath.Abs` 求绝对路径或 config 注入 `builtin_root`。

### G5 · `services/qzda-sandbox/signing/` 是独立微服务代码

签名 Go 代码在 `services/qzda-sandbox/signing/`,不是 `internal/` 子包。

**Why:** 微服务代码隔离
**How:** `internal/skills/signingiface.go` 抽象 `Signer` interface,`services/qzda-sandbox/signing` 实现并通过 `Deps.Signer` 注入;P3 S15 走 mock signer。

### G6 · Skill signing boot 阻塞(`server.go:520–590`)

启动时探测 trust file / dev keypair / vault keystore / key resolver 4 项。

**Why:** Signing 是 platform-critical,启动失败 fail-closed
**How:** P2 阶段 `buildSkillsSvc` 中调用 `Signer.LoadTrustStore()`,失败日志 + 启动阻断;测试用 `signingiface` mock signer 跳过真实 keypair。

### G7 · M02 copilot → M09 builtin loader 反向依赖

`copilot/helpers.go:116-126` mirror `builtin_skills.go:78-88`。

**Why:** 跨模块依赖需 decoupling
**How:** P2 后 copilot 通过 `Deps.BuiltinSkills` 函数值注入。

### G8 · `pages/Skills.tsx` 1584L 拆分对 diff 的影响

接近 M07 `Knowledge.tsx` 1298L 的 1.2 倍。

**Why:** TSX 门禁硬约束(≤400L)

### G9 · 20 路由全走 `s.skillsSvc.*` 调度

`skill_artifacts*.go` 4 文件 2464L 是 office 文档生成,严格说是"被 M09 使用"的子能力。

**Why:** artifacts 与 skills 业务逻辑解耦

### G11 · M05 `agentSkillBind` 跨模块入口

`/api/agents/{id}/skills` 在 M05,迁完后调 `s.skillsSvc.BindSkillToAgent`。

**Why:** 跨模块入口需统一
