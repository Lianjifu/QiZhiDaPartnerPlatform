## 一、背景与目标

### 1.1 背景

运营总览(M01)是平台首页,三角色通用。代码当前跨多个目录:

- **前端**:页面在 `pages/Home.tsx`(809L —— **超 TSX ≤400L 门禁 ~2 倍**);纯函数逻辑在 `features/home/`;类型 + live aggregate 镜像在 `packages/api/src/home-live-aggregate.ts`(515L);mock handlers 在 `mock.ts` 里 4 处
- **后端**:核心聚合在 `internal/server/ops_aggregate.go`(534L);HTTP wrapper 散在 `internal/server/handlers_e.go`(218L 中只有部分属于 M01);store seed 在 `internal/store/store.go`
- **微服务占位**:`backend/services/qzda-sys/internal/domain/ops/doc.go`(75 字节,空文件) — 计划中的 `de-ops` 微服务未实现,M01 逻辑全部在 monolith

文件大小门禁:`pages/Home.tsx` (809L) **严重超 TSX ≤400L**,需先拆再合。

### 1.2 目标

- **前端**:`grep frontend/web/src/features/dashboard/` 能找全所有 M01 代码(包含聚合 + 渲染 + i18n + 类型)
- **后端**:`grep backend/internal/operations/` 能找全所有 M01 handler + 聚合 + 注册
- **行为零变化**:KPI 计算口径、spotlight/calendar/ROI/告警确认语义、mock 数据形状、audit 文案、env 标志全部保留
- **为未来抽 `de-ops` 微服务铺路**:`internal/operations/` 自包含,不依赖 `*Server`

### 1.3 不在范围内

| 项 | 说明 |
|---|---|
| 实现 `services/qzda-sys/internal/domain/ops/`(微服务抽离) | 本次只重排 monolith 代码;不创建新的微服务 |
| 新增 API 路由 / 字段 | M01 现有 7 个路由(`/api/home/*` + `/api/operations/overview`)不变 |
| 改 KPI 计算口径 | `employeeHealthScore` / `taskSuccessRate` / `aggregateByHour` / 等纯函数算法不变 |
| 改 `HomeExtraLive` / `OpsOverviewLive` 类型 | 前端 `home-live-aggregate.ts` 是后端 `ops_aggregate.go` 的镜像,字段不变 |
| 改 Mock 种子数据 | mock handler 返回形状不变 |
| 抽运营总览的 store(Zustand) | M01 当前无专属 store(全部用 TanStack Query);不引入 |
| 重写 CSS class 名(`home-page`、`home-kpi` 等) | 跨多页面共用,不重命名 |

### 4.5 mock handler 拆分策略

`packages/api/src/mock.ts` 是单文件 49 万行(yes,really)的 mock 大全集。M01 占其中 ~200 行。

**两方案二选一(决策 #6):**

**A. 保持 `mock.ts` 单文件**,M01 handler 块用 `// region: 运营总览` 注释包围,不物理拆分
- 优点:改动小,所有 mock 仍集中
- 缺点:`mock.ts` 仍是巨型文件

**B. 拆出 `dashboard/mock.ts`,`mock.ts` 仅 `import { m01MockHandler }`**
- 优点:与本次整合目标一致(`features/dashboard/` 自包含)
- 缺点:动到 mock 文件;mock.ts 里其它 handler 的 `ctx.store.xxx` 引用可能跨 handler 共享状态

**推荐 B**:每个功能模块将来都要拆,这次开个头。

### 5.4 `operations.Handler` 接口设计(与登录 `auth.Handler` 对齐)

```go
// operations/http.go
package operations

import (
    "net/http"
    "time"
)

// AggregateStore is the read surface needed by aggregate.go.
// server/ wires this to *store.Store.
type AggregateStore interface {
    RLock()
    RUnlock()
    AppendAudit(workspaceID, actorName, action, category, status, detail string)
    Employees  // see below — exposes the typed collections needed
    // ...
}

// Handler holds all HTTP handlers for /api/home/* and /api/operations/overview.
type Handler struct {
    Store      AggregateStore
    AuditActor AuditSink  // func(workspaceID, actorName, action, ...) — see auth.AuditSink pattern
}

func (h *Handler) Routes() []Route { ... }
```

聚合函数(`opsOverviewLive` 等)当前是 `*Server` 的方法。它们从 `s.Store` 读数据。重构时:

- 把 `s.Store` 用 `AggregateStore` interface 注入
- 聚合函数变成 `(h *Handler)` 的方法或包级函数 + `*AggregateStore`
- `Server.buildOpsHandler()` 在 `New()` 里装配
