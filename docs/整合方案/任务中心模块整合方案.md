## 一、背景与目标

### 1.1 背景

M03 任务中心是平台的"任务化运营面":把对话/事件任务化,看板 + 列表视图,支持人工治理与审计追溯。

代码当前形态:

- **前端**:`pages/Tasks.tsx` 单文件 **155L**(在 TSX ≤400L 门禁内);无 `features/tasks/` 目录
- **后端**:`backend/internal/server/task_*.go` 共 **4 个文件 / 839 LOC**,全部在 `internal/server/`:
  - `task_domain.go` **546L**(>500L 建议上限;接近上限,**建议拆为 task_domain.go + task_domain_extra.go**)
  - `task_domain_test.go` 137L
  - `task_center_api_test.go` 128L
  - `task_fsm.go` 28L
- **微服务**:`qzda-collab` 脚手架保留;不创建 `qzda-tasks` 微服务(任务模块体量不足以单列)

`internal/server/server.go` 中 M03 路由 4 条(L660-665 + L810-811):
1. `GET /api/tasks` → `s.listTasksAligned(r)`
2. `POST /api/tasks` → `s.createTaskAligned(r)`
3. `GET/POST/PATCH /api/tasks/{id}/*` → `s.taskRoute(r)`
4. `POST /api/conversations/{id}/tasks` → `s.conversationCreateTask(r)`(M02 → M03 跨源依赖)

### 1.2 目标

- **前端**:`grep frontend/web/src/features/tasks/` 能找全所有 M03 代码
- **后端**:`grep backend/internal/tasks/` 能找全所有 M03 handler + 业务 + FSM + tests
- **行为零变化**:lifecycle 6 状态机(pending / running / human_action / risk / completed / archived)、`listTasksAligned` 的 mock 对齐、Ally/Audit 写入、approve/takeover 治理行为全部保留
- **包边界真实**:`internal/tasks/` 自包含,只依赖 `internal/auth/` 与 `pkg/errors`(已盘点确认,**无 server-internal 耦合**)

### 1.3 不在范围内

| 项 | 说明 |
|---|---|
| 创建 `qzda-tasks` 微服务 | 任务体量不足,本次不抽服务 |
| 重写 lifecycle FSM | 现有 `task_fsm.go` 28L,逻辑保留 |
| 拆 `pages/Tasks.tsx` 子组件 | 155L 已满足 TSX ≤400L,本次只做**目录迁移**,不拆组件 |
| 引入 Zustand store | 当前无 store,沿用 TanStack Query + useRef(同 M02 模式) |
| 重命名 `task` → 其它 | 跨系统协议名,以 `task` 命名,不重命名 |
| 抽取 FSM 抽象 | task_fsm.go 自含,无外部依赖,不变 |

## 五、Gap 与风险

### G1 · `task_domain.go` 546L 拆分对 diff 的影响

546L 拆为 2 文件需要识别代码边界。已列 internal/auth + pkg/errors 依赖,**无隐藏 server 依赖**,拆 diff 可控。

**Why:** 略超 500L 建议上限,视觉搜索成本上升
**How:** 按方法签名切分(align/CRUD/治理 三块),每块 ~180L

### G2 · 现有 `task_center_api_test.go` 删除会否丢覆盖?

review 后再删,确认覆盖被新 `integration_test.go` 吸收。

**Why:** 双份集成测试维护成本高
**How:** P3 阶段先 diff 两份测试的用例,确保新覆盖 ≥ 旧覆盖

### G3 · `conversationCreateTask` 跨模块入口(M02 → M03)

迁移后该方法从 `*Server` 搬到 `*tasks.Service`。`server.go` L810-811 路由改为 `s.taskSvc.ConversationCreateTask(r)`。

**Why:** M02 已封装为 internal/copilot,P2 deep-move 后该方法搬到 internal/tasks
**How:** P2 deep-move 完成后,顺手完成跨模块入口调整

### G4 · M03 P2 与 M02 P2 deep-move 并行?

不能并行——都改 `internal/server/server.go`。建议 **M02 P2 deep-move 完工后**再开始 M03 P2;M03 P1 前端可与 M02 P2 后台并行。

**Why:** server.go 同文件并发改动冲突
**How:** P1(frontend) + P3(tests) vs M02 P2 并行;P2 等 M02 P2 deep-move 完工
