## 五、Gap 与风险

### G1 · `handlers_knowledge.go` 1926L 单文件拆分

1926L 是迄今 backend 单文件最大段(超过 M06 1269L、M08 1269L)。

**Why:** 25 个 handler 集中在一文件,必须按主题拆
**How:** §3.2 表已给 6 文件切分,执行时若某段 <200L,合并到相邻文件。

### G2 · Connect-RPC binding 跨包迁移

`ragConnect` 当前在 `connect_services.go`,接收 `*Server`。迁到 `internal/knowledge/connect.go` 后,接收 `*knowledge.Service`(同 M05 partnerConnect 模式)。

**Why:** Connect-RPC 与 HTTP 路由并行,绑定到模块自己的 Service
**How:** `connect.go` 中 `new(s *Service)` 构造器,`server.go` 初始化时 `knowledge.NewConnect(s.knowledgeSvc)`。

### G3 · builtin tool `knowledge.retrieve` 注入 copilot

`builtin_knowledge.go` 在 server.go:238 注入 copilot registry。迁完后注入路径 `Deps.RegisterBuiltinTool = s.knowledgeSvc.RegisterBuiltinTool` 或在 `buildKnowledgeSvc` 后立即调用 `s.copilotSvc.RegisterBuiltinTool("knowledge.retrieve", knowledgeSvc.RetrieveBuiltin)`。

**Why:** copilot 依赖 knowledge builtin
**How:** 同 M05 模式 — Deps 函数值注入。

### G4 · `server/session_panel → citation/citationlog` 反向依赖

`session_panel.go:13,14` 直接 import `internal/knowledge/citation` 和 `internal/knowledge/citationlog`。

**Why:** 跨包依赖需 decoupling
**How:** P2 阶段 `session_panel.go` 改用 `Deps.CitationFn` / `Deps.CitationlogFn` 函数值注入。

### G5 · 4 个子包已被外部引用

`citation` 被 copilot 引用,`citationlog` 被 session_panel 引用,`scope` 被 connect_gateway 引用。子包必须维持独立可访问。

**Why:** 子包是叶子库
**How:** P2 验证 `internal/knowledge/citation/` 不被 `internal/knowledge/handlers.go` import(防止子包被"消化")。

### G6 · `pages/Knowledge.tsx` 1298L 拆分对 diff 的影响

3.2× 超 400L 门禁,拆 7-8 文件。

**Why:** TSX 门禁硬约束
**How:** 按 tab 拆(docs/packages/sources/governance/jobs/eval)+ modal + shared,复用现有 7 个 feature 文件。

### G7 · 25 路由全走 `s.knowledgeSvc.*` 调度

server.go L824-L882 共 25 条路由,需全部 wire 到 `s.knowledgeSvc.*`。

**Why:** 消除 `*Server` 直调
**How:** 同 M06 — 25 路由逐一对应到 Service method,无 fallback receivers。
