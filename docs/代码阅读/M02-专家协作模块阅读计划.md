### Subsystem 4 — 跨会话记忆

**读取（copilot_context.go:291-428）：**

- 过滤顺序：workspace → status=active → MemoryCanRead → layer ∈ {short/working/long} → 未过期 → **DE-id 严格隔离** → short_term 去重 → owner-only
- 无 query tokens：只保留 working/long_term，按 layer 排序，封顶 5 条
- 有 query tokens：BM25 + MMR（`memret.Score`）→ 预算选择（`membudget.Select`，预算 1000 token）

**DE-id 隔离修复**（copilot_context.go:315-324）：旧判断 `deID != "" && memDE != "" && memDE != deID` 在 `memDE == ""` 时短路为 false，导致未绑定 DE 的记忆（管理员手工摄入、task 写入）会泄漏到所有专家。新判断 `deID != "" && memDE != deID` 严格隔离。

**两路打分分支：**

- **无 query tokens**（line 355）：保留 working/long_term，按 `layerRank`（long_term=3, working=2, short_term=1）排序，封顶 `copilotMemoryMaxItems = 5`。合成 `Score = 0.3 + 0.1*layerRank`
- **有 query tokens**（line 380）：构建 `[]memret.Doc` 语料，用 BM25 + MMR 打分（`memret.Score`），喂给 `membudget.Select`（预算 `copilotMemoryBudgetTokens = 1000`）

**Token 预算选择**（`internal/memory/budget/budget.go:52`）：`Select(cands, budgetTokens, 0.5)` 按 `(priority desc, score desc, recency desc)` 排序 → 走预算 → `truncateAtParagraph` 优先 `\n\n` → 句号 → rune 切。优先级映射在 `copilot_context.go:486-495`：long_term=3, working=2, short_term=1。返回的 `Report{UsedTokens, Kept, TruncatedItems, DroppedIDs}` 喂给 SSE `memory.budget` 事件。

**Provenance 输出：** `memoryProvenanceMaps(hits)`（`copilot_context.go:258-272`）把 `[]memoryHit` 转成 `[]map[string]any`（`{id, title, layer, score}`），给白盒审计。

**Memory budget SSE flush：** `Service.lastMemoryBudgetReport`（单槽，`service.go:232`）由 `recordMemoryBudgetReport`（`copilot_context.go:459-484`）写入 —— **每次召回都写一条报表，包括空召回**。流处理器通过 `ConsumeLastMemoryBudgetReport` 排空并发 `memory.budget` SSE。每参与者 collector（`participantMemoryBudgetReports` map，`service.go:237`）让 `runMultiAgentTurn` 在面板派发完成后发一条合并事件。

### Subsystem 6 — 上下文压缩（三层机制）

**第一层：硬截断（确定性 rune 切割）**

- `assembleCopilotChatMessages` 滑窗 + `copilotHistoryMaxRunes=1200` / `copilotHistoryPriorRunes=600`
- 工具观察 `reactToolObservationMaxRunes=800`
- 用于回合内历史窗口化和工具观察限长

**第二层：预算感知截断（段落边界）**

- `internal/memory/budget/budget.go:52` `Select(cands, budgetTokens, 0.5)` 按 priority/score/recency 排序 → 走预算 → `truncateAtParagraph` 优先 `\n\n` → 句号 → rune 切
- 产出 `Report{UsedTokens, Kept, TruncatedItems, DroppedIDs}` → SSE `memory.budget` 事件
- 用于跨会话记忆注入

**第三层：语义压缩（Dream）**

- `dreamCompressConversationLocked`（`copilot_evolve.go:215`）把 ≥3 条 short_term 合并成 1 条 working 层摘要
- 源 short_term 标记 `expired`
- 产出 `evolveKindDream` candidate，状态 `applied`

**压缩 vs 截断的区分：**

- **截断** = 确定性 rune 切，不动语义（history / tool 观察）
- **预算截断** = token 感知，按段落切，产出审计报表（记忆注入）
- **压缩** = 多条 → 一条，语义合并（dream）

**Post-turn 演化（`copilot_evolve.go:103`）：**

四种候选类型：

1. `memory_promote`（line 119）—— 偏好类陈述
2. `skill_patch`（line 152）—— 成功工具模式
3. `routing_hint`（line 180）—— 重型模式
4. `dream`（line 206）—— 短时记忆压缩

**接口边界：** `assembleCopilotChatMessages`（历史）、`retrieveMemoryForTurnLocked`（记忆）、`RunPostTurnEvolutionLocked`（回合后）。`Deps.IngestRuntimeMemoryLockedFn` / `Deps.MemoryPolicyForFn` / `Deps.MemoryCanReadFn` 是 server.go 注入点。
