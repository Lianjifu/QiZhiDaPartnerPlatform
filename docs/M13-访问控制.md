# M13 · 访问控制

> **模块 ID**：M13 · **路由**：`/settings?tab=access` · **后端前缀**：`/api/access/*`、`/api/release-approvals/*` · **实现度**：✅
> 导航：[← 索引](./README.md) · 上一模块 [M12 平台设置](./M12-平台设置.md) · 下一模块 [M14 持续验证](./M14-持续验证.md)

**功能**：成员授权、生产发布审批、职责分离。

### 前端

`frontend/web/src/pages/Governance.tsx`（路由 `/governance`；`App.tsx` 对 admin 重定向到 `/settings?tab=access`）。审计员侧栏入口为「访问控制」。

### 后端

- `internal/server/handlers_a.go` — access 与 release-approvals 路由族
- `internal/server/dual_approval.go` — 双签与 SoD 判定
- `internal/policy/engine.go` + `internal/policy/remote.go` — 策略引擎
- `internal/auth/permissions.go` — 角色 → 权限矩阵（`RolePermissions` / `Has`）

### 发布审批队列

| 环节 | 位置 |
|---|---|
| 前端 | `Governance.tsx:36` `GET /api/release-approvals` · `:40` `POST /api/release-approvals/{id}/approve` · `:44` `.../reject` |
| 路由 | `server.go:814-819` → `s.listReleases`（`handlers_a.go:678`）· `s.createRelease`（`:694`）· `s.releaseAction`（`:728`） |
| Handler | 同上三个函数 |
| 校验 | **提交**（`createRelease`）：auditor 禁提交 → `ReleaseRequestForbidden`；`resourceName` / `resourceType` 必填 → `ReleaseRequestInvalid`；`requireWorkspaceAccess`（`internal/server/context.go:201`）；再跑 `s.evaluateZeroTrust(...)`，decision=deny → `apperr.ZeroTrustDeny`。**审批**（`releaseAction`）：`auth.Has(id, "release.approve")`；走 `s.evaluateWrite(r, "release", "approve", policy.Input{ApproverID: id.ID})`（`internal/server/policy_write.go:13`）；**SoD**：`submittedById == id.ID` → `apperr.SODSelfApproval` |
| 落库 | 写 `Store.ReleaseApprovals`(status=pending → approved / rejected) → `release_approvals` → `platform.kv_documents`；`AppendAudit` |
| 错误码 | `ReleaseReadForbidden` / `ReleaseRequestForbidden` / `ReleaseRequestInvalid` / `ReleaseApproveForbidden` / `ReleaseNotFound` / `SODSelfApproval` / `ZeroTrustDeny` |

### 策略引擎（判定来源）

| 环节 | 位置 |
|---|---|
| 入口 | `internal/server/policy_write.go:20` `evaluateWriteLocked` → `:52` `decidePolicy` → `internal/policy/remote.go:21` `Engine.Evaluate` |
| 远端模式 | 设 `QZDA_OPA_URL` 时 `POST {url}/v1/data/de/authz/result`（`remote.go:71`），2 秒超时；失败**静默回退**本地规则 |
| 本地规则 | `remote.go:33` `evaluateLocal` 的 6 条 baseline：<br>① `baseline.auditor_readonly` — auditor 非读动作<br>② `baseline.restricted_egress` — restricted 数据 + 外部出口 + model/channel<br>③ `baseline.sod` — submitter == approver<br>④ `baseline.release_admin` — 非 admin 执行 approve/publish/release<br>⑤ `baseline.published_binding` — 绑定未发布能力<br>⑥ `baseline.default_allow` |
| 副作用 | 每次判定都 `AppendAudit(workspaceID, actor, "policy:"+action, resource, allow/deny, reason)`（`policy_write.go:42`） |
| 错误码 | deny 时返回 `apperr.RoleForbidden`（`policy_write.go:45`） |

> 关键细节：`evaluateWriteLocked` 只在 action == `approve` 时把当前用户填入 `ApproverID`（`policy_write.go:33`）。若对 `submit` / `release` 也默认填，会与 `SubmitterID` 相同而误触发「提交人不可自批」。

### 双签与会签（`internal/server/dual_approval.go`）

| 函数 | 行 | 语义 |
|---|---|---|
| `requiresPeerApprovalGate` | `:17` | 生产态且非 admin → 需要他人会签 |
