# M05 · 数字伙伴

> **模块 ID**：M05 · **路由**：`/partners` · **后端前缀**：`/api/partners/*`、`/api/partner-*` · **实现度**：✅
> 导航：[← 索引](./README.md) · 上一模块 [M04 工作区](./M04-工作区.md) · 下一模块 [M06 工作流程](./M06-工作流程.md)

**功能**：以**岗位**为边界的数字伙伴全生命周期：配置 → 能力装配 → 评测上岗 → 运行运营 → 证据。

`features/partners/components/` — `PartnersPage.tsx`（目录页，5 Tab）+ `PartnerCreatePage` / `PartnerDetailPage` + `PartnersTab.{RoleSetup,Detail,Capability,Release,Operations,Onboarding}` + `PartnersModals.publish.tsx` + `PartnersDelete.tsx` + `PartnersShared.tsx`。
`features/partners/hooks/usePartnerBuiltinToolNames.ts` 提供能力目录中的内置工具名。

### 后端

`internal/partners/`（HTTP façade，2.5k 行）— `service.go`（`Deps` 门面）· `handlers_contract.go` · `handlers.go` · `handlers_actions.go` · `capability_catalog.go` · `connect.go` · `util.go`。
另加 `internal/server/employee_validate.go` / `employee_runtime.go` / `employee_binding.go` / `dual_approval.go`。

## 伙伴的数据模型

伙伴在 store 中是一条 `map[string]any` 记录（`internal/store/store.go:35` 的 `Employees` 集合），出厂 `de-office` 的种子见 [`internal/store/builtin_general.go`](../backend/internal/store/builtin_general.go)。字段语义：

| 字段 | 含义 |
|---|---|
| `id` · `name` · `role` · `department` · `owner` · `ownerId` | 岗位身份与责任人 |
| `version` · `environment` · `lifecycle` · `risk` | 版本、生命周期状态、风险等级 |
| `responsibilities[]` | 职责清单 |
| `prohibitedActions[]` | 禁区清单 |
| `capabilities{model,knowledge[],skills[],tools[],workflows[],channels[]}` | 装配的能力**版本** |
| `boundaryPolicy.capabilityModes[]` | 逐能力的 `execute`/`recommend`/`approval_required`/`prohibited` |
| `memoryPolicy{shortTermHours,workingDays,longTermCadence,knowledgePromotion}` | 记忆分层与晋升策略 |
| `runtime{calls24h,successRate,p95Ms,costToday,handoffs24h,anomalies,replyMode,segmentPolicy}` | 运行证据投影 |
| `evaluation{status,score,lastRunAt}` | 评测门禁 |
| `release{status,releasedAt,requestedById,approverId}` | 上岗审批留痕 |

## 深度能力：契约 · 派生 · 交接 · 轨迹

> 实现细节见 [M16 深度智能体编排](./M16-深度智能体编排.md)。

### 能力契约（Capability Contract）

伙伴装配的不再只是"一个能力名字"，而是一份**可校验的调用契约**（`internal/copilot/copilot_contracts.go`）：入参 schema、产物类型、是否需要审批、执行模式。

| 落点 | 说明 |
|---|---|
| 伙伴载荷 `capabilityContracts` | `internal/server/employee_runtime.go` → `EmployeeCapabilityContracts`；详情页可见每个已装配能力要什么参数 |
| 调用前校验 | `ValidateContractArgs`（`copilot_contracts.go`）→ 挂在 `authorizeToolCall`：参数不合法**不执行**，回结构化错误让模型自纠（`Permission: contract_invalid`） |
| 上岗闸门 | `EmployeeContractIssues` + `validateEmployeeReleaseGates`（`internal/server/employee_validate.go`）：平台内置能力的疑似拼写错误（如 `knowlege.retrieve`）拒绝上岗，错误码 `E_CAPABILITY_CONTRACT_MISSING`；CMDB / 企业自带工具不拦 |

### 派生策略 `delegationPolicy`

伙伴档案新增 `delegationPolicy`（随配置版本走审批，`internal/partners/handlers.go` `applyEmployeeConfig`）：

```jsonc
{
  "enabled": false,            // 默认关闭：不配置就不许派生
  "maxDepth": 1,               // 嵌套深度上限 1
  "maxConcurrent": 3,
  "inheritCapabilities": [],   // 允许传给子伙伴的能力白名单
  "allowedTargets": []         // 允许派生到的目标伙伴 ID 白名单（为空则不跨伙伴）
}
```

运行期实现 `internal/copilot/copilot_delegate.go`：子伙伴**上下文隔离**（不继承主对话历史）、**能力白名单裁剪**、拿不到 `agent` 工具（深度封顶）、只把结论回灌主上下文。

### 交接触发条件 `boundaryPolicy.handoff`

配置期已强制要求 `triggers` + `approvers` 成对出现（`internal/server/employee_validate.go`），本轮补上**运行期实现**：

| 触发 | 判定 |
|---|---|
| `prohibited_action` | 工具被边界策略拒绝 |
| `tool_failure` | 同一工具连续失败 ≥2 次 |
| `user_request` | 用户显式要求转人工 |
| `boundary_exceeded` | 超出岗位职责边界 |

命中后（`internal/server/escalation.go`）：接管人取 `escalationOwner`（上岗闸门强制必填）→ 写 `sess["handoff"]` → 写操作被拦截（`E_SESSION_HANDOFF`）→ 审计留痕并计入 `runtime.handoffs24h`。

### 轨迹评分取代写死分数

`evaluate` 不再写死 `score: 93.5 / 68.0`（`internal/partners/handlers.go`），改为按伙伴**真实运行轨迹**评分（`internal/server/employee_trajectory.go`）：

```
score = 100 − 15×工具失败 − 10×挂起审批 − 20×越界 − 1×超长路径   （通过线 85）
```

结果落 `evaluation.trajectory`（含 `turns` / `toolCalls` / `failures` / `awaiting` / `escalations` / `violations`），伙伴载荷的 `trajectory` 字段同步投影。**没有任何真实回合时 `status=unknown`**：不给假分数，保留结构性评测。

> 前端：`features/partners/components/PartnersDetail.Panels.tsx` 的「能力契约」与「运行轨迹」两个面板 —— 能力详情页逐项列出已装配能力的契约（必填参数 / 产物 / 是否需授权），运行观测页展示轨迹分与最近异常回合；无真实回合时显示「暂无运行轨迹」。

## 边界

- 只引用已发布能力由 `validatePublishedCapabilitiesImpl` 强制，但**能力目录聚合**本身在 split 部署下会走 peer HTTP；单体形态下走本地 store 分片
- `capabilityCatalogAligned` 内部是「peer 聚合 + 本地兜底 + merge」三层，是 M10 折叠后遗留的复杂度点
- 审计员的 partner Connect 服务（`connect.go`）只提供只读投影
