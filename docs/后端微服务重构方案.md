# 后端服务 + 基础服务重构方案（粗粒度进程）

> **版本**：v4.3（2026-08-19）  
> **状态**：**monolith（方案 A）为本地默认；coarse 四进程保留用于规模化**  
> **对齐**：[后端架构规划.md](./后端架构规划.md)（逻辑层 Lxx / 模块 Mxx 仍为真相源）  
> **相对 v3 修订**：  
> - **不按逻辑域拆成 12 个 Go 微服务**  
> - **同类能力合并为一个部署单元、一个端口**  
> - 逻辑模块（platform / policy / …）保留为进程内边界 + 六边形包，便于以后按需再拆  

---

## 0. 定稿原则

| # | 原则 |
|---|---|
| 1 | **粗粒度优先**：一类能力 = 一个进程 = 一个对外端口 |
| 2 | **逻辑可细、进程要粗**：`platform/policy/audit…` 是模块，不是独立微服务 |
| 3 | **Go 六边形**：每个部署单元内按 Ports & Adapters；模块间禁止跨包直连表 |
| 4 | **Python 执行面独立**：推理 / RAG / 沙箱各一端口（隔离要求） |
| 5 | **基础服务分目录**：数据、IdP、策略引擎、观测各自可编排 |
| 6 | **永不混部**：`qzda-sandbox` · `qzda-agent-runtime` · `qzda-rag`（执行面互不混） |

## 1. 部署单元总览（目标态）

### 1.0 方案 A — monolith（本地 / SME 默认）

**gateway :8089 → qzda-app :8100 + qzda-skill :8093**（sys + collab + cap 合一）。

| 部署单元 | 端口 | 说明 |
|----------|------|------|
| qzda-gateway | 8089 | Envoy `envoy.monolith.yaml` |
| **qzda-app** | **8100** | **sys + collab + cap**（`ModeApp`） |
| qzda-sandbox | 8093 | 技能沙箱（必须独立） |
| qzda-workflow（可选） | 8103 | 工作流 |

启动：`make compose-up-monolith` / `make run` / `DE_STACK=monolith scripts/dev-stack/run-stack.sh`。

### 1.1 方案 coarse — 四进程（规模化）

相对「12 个 Go 微服务」，收敛为 **5 个 Go 进程 + 3 个 Python 进程 + 1 个网关**：

```text
Callers
   │

┌────────────┐
│ qzda-gateway │  :8088 / :8443     Envoy（api + agent 入口）
└─────┬──────┘
      │
      ├──────────────┬──────────────────┬─────────────────┐
      ▼              ▼                  ▼                 ▼
┌──────────┐  ┌──────────┐      ┌───────────┐     ┌────────────┐
│ qzda-sys   │  │ qzda-collab│      │ qzda-cap    │     │ qzda-workflow│
│  :8100   │  │  :8101   │      │  :8102    │     │  :8103     │
│ 地基+运营 │  │ 协作编排 │      │ 能力控制面 │     │ 流程+Worker│
└────┬─────┘  └────┬─────┘      └─────┬─────┘     └──────┬─────┘
     │             │                  │                  │
     │             └────────┬─────────┘                  │
     │                      ▼                            │
     │             ┌────────────────┐                    │
     │             │ qzda-agent-      │ :8091 FastAPI      │
     │             │ runtime        │◄───────────────────┘
     │             └───────┬────────┘
     │         ┌───────────┼───────────┐
     │         ▼           ▼           ▼
     │   qzda-rag:8092  qzda-sandbox:8093  （+ Temporal via workflow）
     │

```

| 部署单元 | 端口 | 栈 | 内含逻辑模块（原细拆名） | 逻辑层 |
|----------|------|----|--------------------------|--------|
| **qzda-gateway** | 8088/8443 | Envoy | 统一入口、TLS、路由、限流 | L00·L01 |
| **qzda-sys** | **8100** | Go 六边形 | **platform · policy · audit · ops** | L10·L11·L12·L13 |
| **qzda-collab** | **8101** | Go 六边形 | **collab · employee** | L02 |
| **qzda-cap** | **8102** | Go 六边形 | **model · knowledge · memory · skill · channel** | L04–L07·L09 |
| **qzda-workflow** | **8103** | Go 六边形 | **workflow**（HTTP 控制面 + Temporal Worker） | L08 |
| **qzda-agent-runtime** | **8091** | FastAPI | LangGraph / 流式 / 工具编排 | L03 |
| **qzda-rag** | **8092** | FastAPI | 切片 / Embedding / Milvus / Rerank | L05 |
| **qzda-sandbox** | **8093** | FastAPI + 隔离网 | Skill / MCP 沙箱执行 | L07 |

> **合计业务部署单元**：monolith 默认 2（qzda-app + qzda-skill）+ gateway；coarse 为 8（+ gateway）= 9。  
> **过渡**：~~qzda-core / 8094 / 8095~~ **已退役**；默认 monolith，coarse 用于规模化对照。

### 1.1 为何这样合并

| 单元 | 合并理由 |
|------|----------|
| **qzda-sys** | 地基与合规读写同命运：租户/配额、策略评估、审计写入、运营只读聚合；共享工作区上下文与鉴权 |
| **qzda-collab** | 会话/任务与岗位装配强耦合（发消息 → 解析员工绑定 → 调能力） |
| **qzda-cap** | 能力控制面同类：模型/知识/记忆/技能目录/渠道，均为「配置 + 发布引用」，非执行 |
| **qzda-workflow** | 依赖 Temporal Server；Worker 长驻，与纯 CRUD 控制面生命周期不同，单独一端口 |
| **三个 Python** | 资源、安全、扩缩模型不同；沙箱 必须隔离网 |

### 1.2 明确不做的细拆

以下**不再**各自占用独立端口 / 独立微服务：

`qzda-platform` · `qzda-policy` · `qzda-audit` · `de-ops` · `de-employee` · `qzda-model` · `qzda-knowledge` · `qzda-memory` · `qzda-skill` · `qzda-channel`

它们降级为 **进程内模块名**（包路径 / schema 前缀 / proto package），API 路径可继续按域划分（如 `/api/models/*`），但由同一进程监听。

## 2. 进程内模块与六边形

### 2.1 每个 Go 部署单元目录

```text
services/qzda-sys/
├── SERVICE.md
├── Dockerfile
├── go.mod
├── cmd/qzda-sys/main.go              # Composition Root：一个端口
└── internal/
    ├── domain/
    │   ├── platform/               # 模块实体
    │   ├── policy/
    │   ├── audit/
    │   ├── ops/
    │   └── port/                   # 跨模块端口接口
    ├── application/
    │   ├── platform/
    │   ├── policy/
    │   ├── audit/
    │   └── ops/
    └── adapters/
        ├── inbound/http/           # 按模块分子路由，同 Listen
        └── outbound/
            ├── postgres/
            ├── redis/
            ├── opa/                # qzda-sys 调 infra-opa
            ├── kafka/
            └── opensearch/
```

`qzda-collab` / `qzda-cap` / `qzda-workflow` 同构，仅模块集合不同。

### 2.2 依赖规则

| 层 | 可依赖 | 禁止 |
|----|--------|------|
| `domain/<module>` | 标准库 | adapter、SQL、HTTP |
| `application/<module>` | 本进程 domain/port | 其他部署单元的 internal |
| 跨模块（同进程） | 经 `domain/port` 或 application 门面 | 直接读写对方表 |
| 跨进程 | HTTP/Connect/事件 | 直连对方 schema |

### 2.3 路由归属（对外仍按域，对内一个端口）

| 部署单元 | 示例路径前缀（对齐现有 Mock） |
|----------|-------------------------------|
| qzda-sys | `/api/workspaces` · `/api/settings` · `/api/policy/*` · `/api/zero-trust/*` · `/api/audit/*` · `/api/ops/*` |
| qzda-collab | `/api/sessions` · `/api/tasks` · `/api/employees` · `/api/copilot/*` |
| qzda-cap | `/api/models` · `/api/knowledge` · `/api/memory` · `/api/skills` · `/api/channels` · `/api/channel-control/*` |
| qzda-workflow | `/api/workflows` · Temporal Worker（非 HTTP） |
| qzda-agent-runtime | `/v1/agent/*`（经 gateway `/agent`） |
| qzda-rag | `/v1/rag/*` |
| qzda-sandbox | `/v1/skills/execute` 等 |

Gateway 按路径前缀转发到上述 **4 个 Go 端口 + 3 个 Python 端口**。

## 5. Schema / 数据所有权（按模块，跨进程禁止直连）

| 写所有者（模块） | 所在进程 | Schema 前缀 |
|------------------|----------|-------------|
| platform / policy / audit / ops | **qzda-sys** | `platform.*` `audit.*` … |
| collab / employee | **qzda-collab** | `collab.*` `employee.*` |
| model / knowledge / memory / skill / channel | **qzda-cap** | `model.*` … `channel.*` |
| workflow | **qzda-workflow** | `workflow.*` + Temporal |

跨进程只走 API / 事件。同进程跨模块经 port，不互相 `SELECT` 对方表（便于日后拆分）。

```text

  ··异步··→ qzda-sys（audit / 用量）
```

## 9. 验收标准

- **Monolith 默认**：gateway `:8089` → **qzda-app `:8100`** + **qzda-skill `:8093`**；healthz 返回 `"mode":"app"`。  
- **Coarse 对照**：`:8100 / 8101 / 8102 / 8103` + FastAPI `:8091–8093`（+ gateway）。  
- 每个 `services/de-*` 可独立构建；`domain/` 无驱动 import。  
- 逻辑模块边界清晰（包 + schema + SERVICE.md 模块表）。  
- 沙箱 无控制面 DSN；FE 经 gateway 联调通过（`make smoke-monolith`）。
